# Docker Compose で動く WrongSecrets ラボ：OWASP WrongSecrets でハードコードされたシークレットとシークレット管理の誤りを見つける練習

[English](README.md) | [Français](README.fr.md) | [日本語](README.ja.md) | [Español](README.es.md)

[![check](https://github.com/mitsurutech/lab-wrongsecrets/actions/workflows/check.yml/badge.svg)](https://github.com/mitsurutech/lab-wrongsecrets/actions/workflows/check.yml)

授業でそのまま使える**シークレット管理のラボ**です。学校やカレッジが生徒一人ひとりに専用のデータベース、コンテナ、ブラウザー上のターミナルを渡せる [MitsuruTech ラーニングプラットフォーム](https://mitsurutech.co.uk/ja/learning)で提供しています。生徒にはそれぞれ **OWASP WrongSecrets** の専用コピーが渡されます。コード、Web ページ、設定の中に、わざと下手に偽のシークレットを隠してあるアプリケーションで、**ハードコードされたシークレットを見つける**練習をし、そのシークレットを本来どこに保管すべきだったかを説明します。何もインストールせず、他の人のマシンが危険にさらされることもありません。

ファイルは `docker-compose` ファイルの `compose.yaml` 1つで、自分のマシンでもプラットフォームでも同じように動きます。プラットフォームでは、生徒ごとにインターネットへの出口がない専用のコピーが使えます。

## たった1つのルール

**調べてよいのは自分のコピーの中だけです。** このラボのものはすべて自分専用のコピーの中で動いており、インターネットへの経路も他の生徒への経路もありません。そのため、手が届くのはラボが起動したアプリケーションだけです。自分のものではない Web サイト、ネットワーク、マシンに対しては、ラボでもそれ以外でも、決してツールを向けないでください。英国では、それは[コンピューター不正使用法 1990（Computer Misuse Act 1990）](https://www.legislation.gov.uk/ukpga/1990/18/contents)に違反する犯罪で、ほとんどの国に同様の法律があります。このアプリケーションのシークレットは作り物であり、他人のリポジトリで本物を探す習慣は遊びではありません。授業の最初の話題には、このルールがなぜあるのか、責任ある開示とはどういうものか、がよいでしょう。

## 中身

| サービス | イメージ | メモリ | 内容 |
| --- | --- | --- | --- |
| `wrongsecrets` | [`jeroenwillemsen/wrongsecrets:1.14.1-no-vault`](https://hub.docker.com/r/jeroenwillemsen/wrongsecrets) | 512 MB | WrongSecrets の Web アプリケーション（ポート 8080） |

イメージはプロジェクト自身の `no-vault` ビルドなので、Vault サーバーもクラウドアカウントも不要です。権限のないアカウント（ユーザー 2000）で動き、capability も不要です。イメージがマシン上にあれば数秒で起動し、アイドル時は約 235 MB を使います。イメージは大きく、ダウンロードは約 550 MB なので、新しいマシンでの初回起動は時間がかかります。

イメージはサードパーティのプログラムで、プロジェクト自身の公開イメージを無変更で実行し、リリースに固定しています（`latest` は使いません）。そのため、授業のあいだにラボが変わることはありません。ここでは何もビルドせず、このリポジトリのものがイメージの中で配布されることもありません。

3. 公開します。各生徒のコピーは公開したコミットから始まるので、あとからここを変更しても、すでに出したラボは変わりません。

残りはヘルプマニュアルの[このラボのガイド](https://mitsurutech.co.uk/ja/help/lab-wrongsecrets)、[セキュリティラボのガイド](https://mitsurutech.co.uk/ja/help/security-labs)、[コンテナラボのガイド](https://mitsurutech.co.uk/ja/help/labs)をご覧ください。compose ファイルに書けること、コピーごとのメモリ、教員が生徒のコピーを開き、見て、採点する方法を説明しています。

## 自分のマシンで動かす

Compose プラグイン付きの Docker が必要です。初回の起動でイメージをダウンロードします。

```bash
docker compose -f compose.yaml -f local.yaml up
```

<http://localhost:8080> を開きます。アカウントを作る必要はありません。**Challenges** メニューからチャレンジを選びます。

`local.yaml` はポートを `127.0.0.1` だけに公開するので、ラボには自分のコンピューターからだけ到達でき、ほかのどこからも到達できません。`Ctrl-C` で止め、`docker compose -f compose.yaml -f local.yaml down -v` で削除します。

## 取り組み方

1. **Challenge 0 から始める。** ゲームの説明があります。どのチャレンジも、うまく隠されていない、または設定されていないシークレットを1つ見つけ、それを入力して Submit を押すものです。Challenge 0 の答えはページ上にあります。
2. **課題文とヒントを読む。** 各チャレンジには、どんな種類の弱点かが書かれていて、行き詰まったときに開けるヒントがあります。
3. **開発者や攻撃者が探す場所を探す。** このラボでは、ページそのもの、ブラウザーの開発者ツール、そしてラボの隣のターミナルです。ターミナルでは `curl` がポート 8080 の `wrongsecrets` という名前でアプリケーションに届きます。たとえば Challenge 16 はフロントエンドのコードに残されたシークレット、Challenge 42 はアプリケーションの監視用エンドポイントが何を漏らすかを扱います。
4. **説明する。** 見つけたシークレットごとに、それがどこにあったか、どうやって見つけたか、その場所がなぜ間違っているか、シークレットをどこに保管すべきかを書きます。

## 教員向け

このラボには、正解に対するアプリケーション自身の緑のチェックマークを除いて、自動採点するものはありません。生徒が証拠を提出し、ほかのラボと同じように教員が採点します。

**証拠は2つに分けて求めてください。** 1つめは作業の証明です。解いたチャレンジごとのスクリーンショットで、ブラウザーにラボ自身のアドレスが写っていて、本人のコピーだとはっきりわかるものです。2つめは理解です。チャレンジごとに、シークレットがどこにあったか、どうやって見つけたか、その場所がなぜ間違っているか、チームは代わりに何をすべきか（シークレットマネージャー、イメージの外に置く環境設定、コミット前のシークレットスキャン）を、自分の言葉で書いた説明です。2つめで、理解したのか、解説のコピーなのかがわかります。

**コースの中での位置づけ。** WrongSecrets はセキュアコーディング、DevOps、ソフトウェアサプライチェーンの単元に向いています。コードとバージョン管理の中の認証情報、コンテナイメージと設定の中の認証情報、フロントエンドのコード、ログと監視を扱えます。正確な文言はご自身の認定機関の単元でご確認ください。ここでは引用していません。

**誰が何を見るか。** こうしたラボは16歳と17歳の生徒に使われることが多くあります。コピーは、起動した生徒本人だけのものです。そのモジュールを教える教職員は、生徒が何をしたかを見るためにコピーを開くことができ、生徒の作業を開くとアクセスログに記録されます。このログは生徒本人が読めます。

## ラボでできないこと

**ここで解けるチャレンジは一部だけで、これはラボの設計によるもので、不具合ではありません。** ラボのコピーにはインターネットへの出口がなく、中にあるのはアプリケーションだけです。プロジェクトのリポジトリを GitHub からクローンする、アプリケーション自身のコンテナの中でシェルを開く、クラウドアカウント、Vault、Kubernetes を使う、AI サービスや別の Web サイトと通信する、といったチャレンジはできません。ページそのもの、アプリケーション自身のエンドポイント、ブラウザーがダウンロードするものに関するチャレンジはできます。Challenge 0、16、42 は、このリポジトリのテストで確認されています。`no-vault` イメージには Vault 関連のチャレンジはありません。アプリケーションは何も記憶しません。ラボを停止してから起動し直すと新しいゲームになり、解いたチャレンジは覚えていません。

## トラブルシューティング

- **「起動」の直後にページが表示されない。** 数秒待ってからもう一度「開く」を押してください。ラボは、アプリケーションがヘルスチェックのアドレスに応答してから準備完了と表示します。
- **チャレンジが、ラボにないものが必要だと言う。** 上で説明したチャレンジのひとつです。別のものを選んでください。
- **自分のマシンでポート 8080 がすでに使われている。** `local.yaml` の左側の数字を、たとえば `127.0.0.1:8081:8080` のように変えて、そのポートを開いてください。

## ラボの検査

`test/check.sh` は、プラットフォームのランナーが各サービスを起動するのと同じ方法でラボを起動し（すべての capability を外し、`no-new-privileges`、プロセス数の上限、メモリの上限を設定し、インターネットへの出口なし）、そのネットワークの内側から、このページが約束していることを確かめます。Docker が必要で、push のたびに実行されます。それが先頭のバッジです。

```bash
test/check.sh
```
